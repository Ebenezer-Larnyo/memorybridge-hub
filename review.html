Evidence checklist (all eight required)

Pass = independently checked against the actual source; Concern = a problem; Not applicable = explain why in notes.

Next: GitHub opens a prefilled issue. You must submit that issue while signed in. A workflow verifies write permission, validates the record and proposes a pull request. Another reviewer should inspect and merge it. This dashboard does not directly approve resources.

How protection works

  1. Human assessment: you inspect the source and record the eight checks.
  2. GitHub authentication: you sign in to GitHub and create the prepared public review issue. No password or token is entered here.
  3. Trusted reviewer check: GitHub Actions verifies that the issue author has write/maintain/admin access before processing anything.
  4. Audit trail: a validated decision becomes a proposed ledger change in a GitHub pull request.
  5. Independent publication: a project maintainer reviews and merges the PR. The daily refresh and Pages deployment then update public badges.

Resource approval means the directory listing passed its review checklist, not clinical validation, professional endorsement or treatment guidance.
